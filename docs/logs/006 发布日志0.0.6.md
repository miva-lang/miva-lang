# 🎉 Miva v0.0.6 Released
> **Clairvoyant Falcon**

我们很高兴地宣布 **Miva 编程语言 v0.0.6** 正式发布！

本版本聚焦于**夯实表达力、扩展标准能力、铺平工具链基础**，让 Miva 从"可玩"迈向"可用"。

---

## 🔧 核心更新

### 1. 控制流结构上线

控制流逻辑从此可用：

```miva
for i in (range(5, 10)) {
  printlns!("i is", i)
}
// 等价于
i := 5
while (i < 10) {
  printlns!("i is", i)
  i = i + 1 // 暂时有 BUG
}
// 等价于
i := 5
loop {
  printlns!("i is", i)
  i = i + 1 // 暂时有 BUG
  if (i >= 10) {
    // break // 未来支持
  }
}
```

---

### 2. 模块语法更新

0.0.6 的模块定义语法从 `module "xxx"` 升级到了 `module xxx`，便于检查器检查非法格式。

```miva
// v0.0.5
module "foo.math"

// v0.0.6
module foo.math
```

这属于破坏性更改，代码需进行简单重写。

---

### 3. 内置警告

0.0.6 为一些函数提供了内置的弃用警告，例如 `prints`（不是宏）：

```miva
prints("Hello ", "World!") // 会输出 Warning，不影响编译
```

同时，0.0.6 将风格检查落到实处。当模块名不是纯小写，或变量名、函数名不符合下划线命名风格时，编译器同样会输出 Warning。

---

### 4. 更好的错误管理

错误管理更加完善，一个文件中的所有错误会一起输出：

```miva
// 示例问题代码
// 缺少 module
main = () => {
  printx("Hello") // 函数不存在
  a = a + 1       // 变量不存在
}
```

在 0.0.5 中，这些错误会逐个输出，影响调试体验。0.0.6 中，所有错误会一并展示，方便一次性修改。

---

### 5. 类型检查

0.0.6 将类型检查提升到了 Semantic 阶段：

```miva
module main
main = () => {
  a = 1 + true // 0.0.5 会隐式成功，0.0.6 会直接报错
}
```

类型检查功能目前还有一些已知问题，将在 0.0.7 带来更好的修复与优化。同时，无论函数是否标记为 `unsafe`，都需要接受类型检查。

---

### 6. miver 发布

安装 Miva 从此不再折腾：

```bash
bash -c "$(curl https://raw.githubusercontent.com/hunter-hongg/miver/script/install.sh)"
# 按照向导安装与激活
miver init   # 初始化 Miver
miver list   # 查看可用版本
miver switch v0.0.6   # 激活 0.0.6
```
